# Sonder v2 — from engine to experience

v1 proved the thesis: any live feed in, coherent music out, natively or in a browser.
v2 makes it *good*, *legible*, *shareable* and *present*. This is the scope; each item is
checked off when it is implemented, tested and deployed.

## A. Musical depth (the ceiling)
- [x] **Form engine** (`sonder-compose`): `conductor.form` — `arc` (intro→build→peak→release
      arcs steered by energy), `sections` (A/B/A'/B' with motif recall), `static`. Sections
      shape density/register/tension targets and chord-change rate; `FormSnapshot` in the
      snapshot; `NextSection` command.
- [x] **Motifs**: melodic generators remember short phrases (per key/degree), restate and
      transform them (transpose, invert, augment) per `motif_recall`.
- [x] **Call-and-response**: salient events on one layer (big trade, strike, loud onset) are
      answered by melodic layers a beat later (`call_and_response`); notes carry `reason`.
- [x] **Note causes**: every event-triggered note carries `NoteSnapshot.cause` (event, time,
      label, attrs).
- [x] **Granular live-audio instrument** (`sonder-dsp`): `Wave::Grain` reads the layer's live
      audio ring (`SynthCommand::AudioChunk` from `audio.features` / browser mic+stream),
      pitched to the note. The ocean becomes the instrument.
- [x] **Physical models**: `Wave::String` (Karplus–Strong), `Wave::Modal` (resonator bank).
- [x] **Mastering**: loudness targeting (`target_lufs`), bus glue compressor, true-peak-ish
      limiter; per-scene mix sanity test (all scenes render within −20..−12 LUFS-ish).

## B. Legibility (the data story)
- [x] **Captions**: `caption` templates on layers/recipes (`"{size} {product} {side} on
      Kraken"`), formatted by the engine into `EventSnapshot.label`, `NoteCause.label`, and
      `EngineSnapshot.captions` for salient moments (intensity / rarity / first-of-kind).
- [x] **Attribution in the UI**: hover/click a note in the piano roll → its cause; click an
      event → the notes it made; captions ticker on the stage.
- [x] **Live Earth**: a world-map view that plots every geo-tagged event from every layer.
- [x] **Form display**: section/arc/motif in the header, in the TUI and the web UI.

## C. Shareability (a platform)
- [x] **URL scenes**: `#s=<deflate+base64 TOML>` — a scene lives in a link; "copy link".
- [x] **In-browser scene editor**: edit TOML with live validation, apply instantly (worker
      restart), fork a built-in, save/load local scenes.
- [x] **LLM scene composer**: `sonder compose "<prompt>"` (native, Claude API) and a
      browser prompt box (user-supplied key kept in localStorage) → validated scene, with
      the full source/recipe catalog and expression reference in context; retries on
      validation errors.
- [x] **Native hot reload**: `UserCommand::LoadScene` restarts the engine in place.

## D. Presence
- [x] **Sonder Radio**: `sonder radio <scene> --out icecast://… | dir/ | file` streams a scene
      24/7 as ogg/mp3 (or HLS) via ffmpeg; docs/RADIO.md for a $5 VPS setup.
- [x] **Daily record**: a workflow renders a dated track (offline + a live capture) and
      publishes it to the site as an "album" page with the day's captions.
- [x] **Overpass kit**: Raspberry Pi notes — camera → `camera.mjpeg`/`camera.jpeg`, kiosk
      web UI, systemd unit.

## Deferred to v2.1
Detection models for cameras (candle/ONNX), OSC / Ableton Link / CLAP plugin, shared
listening rooms, personal feeds (Home Assistant, Strava, calendar).
